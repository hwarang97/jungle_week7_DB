Git 전략

브랜치 구조

main ← 팀 확정 코드만 올라감 (사이클마다 선정된 코드)
├── naco ← 나코 개인 작업용
├── dragon ← 드래곤 개인 작업용
├── hyeonok ← 현옥 개인 작업용
└── jihyun ← 지현 개인 작업용



폴더 분리가 아니라 브랜치 분리를 추천해. 이유는 사이클마다 "선정된 코드를 main에 올리고 전원이 pull 받아서 다시 시작"하는 흐름이 브랜치가 훨씬 깔끔해. 폴더로 나누면 같은 파일이 4벌 공존하니까 어떤 게 최신인지 헷갈려.

사이클 흐름

사이클 시작 시:

git checkout main
git pull origin main
git checkout naco       # 자기 브랜치로 이동
git merge main          # 최신 확정 코드 가져오기



탐색 45분 동안: 자기 브랜치에서 자유롭게 작업. 커밋도 자유롭게.
공유 15분에 선정되면:

# 선정된 사람이 실행
git checkout main
git merge naco          # 자기 브랜치를 main에 병합
git push origin main



선정 안 된 사람: 아무것도 안 해도 돼. 다음 사이클 시작할 때 main pull 받으면 자동으로 선정된 코드로 갈아타게 돼.

수렴 단계 (16:00 이후)

사이클이 끝나고 분담 작업할 때는 기능 브랜치로 전환해.

main
├── feat/benchmark      ← 벤치마크 담당
├── feat/test           ← 테스트 담당
├── feat/edge-case      ← 엣지케이스 담당
└── feat/cleanup        ← 코드정리 담당



각자 작업 끝나면 main에 머지. 이때는 파일이 겹칠 일이 거의 없어서 충돌 걱정 없어.

커밋 메시지 규칙

간단하게만 잡아. [사이클1] 구조체 정의 + search 구현, [사이클2] insert + split 구현, [벤치마크] 100만건 INSERT 측정 코드 정도. 앞에 태그만 붙이면 나중에 히스토리 볼 때 편해.

주의사항

main에는 절대 직접 push하지 않기. 항상 사이클 공유 시간에 전원 합의 후 선정된 사람만 머지. 이게 안 지켜지면 "어? main이 바뀌었는데 뭐가 들어온 거지?" 혼란이 생겨.
